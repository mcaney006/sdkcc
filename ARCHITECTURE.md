# Architecture

## Implemented vertical slice

```text
bytes
  -> libyaml/simdjson syntax parser
  -> arena-backed ParsedDocument with source locations and interned strings
  -> OpenAPI semantic lowering
  -> frontend-neutral NAIR with stable integer IDs
  -> deterministic preparation pass
  -> C23 and C++23 backends
  -> generated SDK using the C23 sdkcc runtime ABI
  -> caller-selected transport (the tests use the in-memory transport)
```

The OpenAPI frontend does not leak parser nodes into NAIR and neither backend
receives OpenAPI objects. A future frontend must only lower into NAIR. A future
backend consumes the same prepared NAIR.

The compiler allocates parsed nodes, interned strings, and NAIR containers from
monotonic `std::pmr` resources. IDs, rather than addresses, connect graph nodes.
Major stages accept const input and produce a separate result so later
incremental or parallel work does not require shared mutable compiler state.

The runtime is C, not C++ behind `extern "C"`. Public implementation objects are
opaque. All public functions carry a `sdkcc_v1_` symbol prefix. Generated C++
is an RAII and `std::expected` layer over exactly the generated C ABI.

## Inputs, state, transformations, outputs

- **Input:** untrusted OpenAPI 3.1 YAML or JSON plus explicit compiler options.
- **State:** per-compilation source arena, string interner, diagnostics, parsed
  document, and NAIR. There is no required process-global state.
- **Transformations:** surface parse, subset validation, OpenAPI lowering,
  name canonicalization/collision checks, dependency preparation, emission.
- **Interfaces:** stable IDs inside the compiler; versioned C ABI between
  generated SDKs, the runtime, and transports.
- **Output:** deterministic source files and a small generated CMake target.

## Runtime boundaries

Generated endpoint code owns protocol policy and model serialization. It calls
the runtime request builder and transport vtable; it never calls curl. A
transport receives an immutable opaque request and returns an owned response.
Allocator provenance travels with every owned runtime buffer.

The Milestone 1 JSON reader visits an object once without building a DOM.
Values are retained as borrowed raw slices and decoded only for fields selected
by generated code. Nesting and arithmetic are bounded.

## Determinism

Input order is preserved where it is semantically visible. Compiler-generated
collections are sorted by explicit stable keys before emission. No timestamps,
addresses, random values, locale-dependent transforms, or unordered-container
iteration enter generated bytes. Integration tests generate twice and compare
file manifests and contents.

## Major risks

1. **Premature ABI freeze.** V1 exposes only opaque handles and small owned/view
   value types; add ABI surface only with executable compatibility tests.
2. **Hostile reference graphs.** `$ref`, recursion, external fetch policy, and
   resource budgets are intentionally not claimed in the first subset. They
   require a bounded resolver before broader schema support.
3. **Ownership explosion.** Request views and response-owned models are kept
   distinct. Shared model generation must preserve that distinction rather
   than papering over it with ambiguous pointers.
4. **Async cancellation races.** No fake async facade is shipped. The future
   executor/transport contract must be proven with cancellation race tests and
   TSan before coroutine syntax is exposed.
5. **C23 portability.** Clang is the primary strict-C23 lane. Windows will use
   clang-cl until the MSVC C frontend implements the required language subset.
6. **Generated-code bloat.** Backends emit boring direct code. Size and compile
   time must be measured before adding generic/template machinery.

## Deliberately deferred

The current slice does not claim recursive schemas, unions, multipart,
pagination, retries, streaming, curl, remote references, or async. Each arrives
as a vertical capability with tests through generated native code; placeholder
interfaces are not substitutes for implementations.
